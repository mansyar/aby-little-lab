The executor could not delete `node_modules` (shell permission), so its frozen

empty tree:

was removed afterwards and the tree was clean before the gate.

### What the lockfile actually did

- `lockfileVersion` stayed `'9.0'` — no format migration.
- pnpm 12 wrote a leading document recording the pin:
  `importers .: packageManagerDependencies: pnpm: specifier 12.16.1`, which
  brought 14 `@pnpm/exe.*` platform entries into `packages` and `snapshots`.
  This is pnpm's own behaviour once `packageManager` is declared, and it is
  accepted rather than suppressed: it is the first time the lockfile records which
  pnpm must run, which was the original defect. `linux-x64-musl` is among the
  variants, so the alpine build stage is covered.
- `serve` and its unique transitive packages were removed. The remaining
  `serve`-substring hits in the file are `@babel/plugin-transform-reserved-words`
  and `supports-preserve-symlinks-flag` — unrelated.
- No kept dependency's resolved version moved. `has-flag` and `supports-color`
  gained `optional: true`, which is metadata, not a resolution change.
